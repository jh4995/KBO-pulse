# perf — DB 튜닝 실험 체계

2학기 졸업논문("부하테스트 기반 Redis 분산 제어 패턴 적용에 따른 투표 시스템 성능 비교 분석")의
**DB 사용 → DB 튜닝 → Redis 사용** 3단계 비교를 위한 측정 체계와 결과를 둔다.
선정 실험은 E0(기준), E2(shared_buffers, E1 진단 포함), E4(복합 인덱스), E7a(Materialized View), E7b(집계 테이블 + 트리거)다.

- 1학기 자산(`k6/*.js`, `db/`, `docker-compose.yml`)은 그대로 두고, 2학기 실험용 파일은 전부 이 폴더에 만든다.
- 측정 원본과 실험별 기록은 `perf/results/<실험ID>/` 에 남긴다 — `card.md`(측정 전 사전 등록), `notes.md`(결과와 해석), 나머지는 스크립트 산출물.

## 1. 구성

| 경로 | 내용 | 작업 |
|---|---|---|
| `docker-compose.perf.yml`, `pg/` | 자원 제한, PG 설정 파일 마운트 | PREP-2 |
| `sql/seed_perf.sql`, `scripts/build_template.sh`, `scripts/reset_db.sh` | 결정적 시드, 템플릿 DB, 리셋 | PREP-3 |
| `scripts/run_experiment.sh`, `sql/`, `k6/ranking.js` | 지표 수집, 한 번에 실행하는 측정 | PREP-4 |
| `k6/mixed_1561.js` | 투표 + 랭킹 혼합, 반영 지연, 락 대기 | PREP-5 |
| `checks/` | 위 체계의 인수 검사 | 각 PREP |

사용법과 산출물 형식은 각 작업이 끝날 때 이 문서에 채운다.

## 2. 측정 기준선 변경 기록 (E0 이전 적용 변경)

1학기 DB 사용 조건과 2학기 E0 사이에 측정 대상 경로(DB 모드 투표 · 랭킹 쿼리, PG 설정, 커넥션 풀, 시드, 자원)를 바꾼 변경을 모두 적는다.
1학기 수치와 E0 를 비교할 때 이 표가 차이의 설명이 된다.

| 변경 | 작업 ID | 영향 경로 | 비교 가능성 영향 |
|---|---|---|---|
| (PREP-1 완료 시 기록) | PREP-1 | DB 모드 투표 | |
| 컨테이너 자원 제한 · 새 시드 | PREP-2 · PREP-3 | 전체 | 1학기 수치와 직접 비교 불가 — E0 를 새로 측정한다 |

## 3. 중간보고서 서술과 코드의 차이

중간보고서(2026-10-19 제출)의 서술 중 코드 · 실제 DB 와 다른 것을 적는다. 결과보고서를 쓸 때 이 표를 반영한다.

| 보고서 위치 | 보고서 서술 | 코드 사실 | 처리 |
|---|---|---|---|
| 본론 §2.3 인덱스 | votes 에는 UNIQUE(user_id, game_id) 인덱스가 있고, game_id 로 찾는 랭킹 조회에는 활용되기 어렵다 | `idx_votes_game(game_id)` 이 스키마에 있다 (`db/schema/01_tables.sql:307`) | E0 의 EXPLAIN 과 실제 DB `\d votes` 로 확인 후, 결과보고서에서 E4 의 비교를 "단일 인덱스 → 커버링 인덱스"로 서술 |

## 4. 클라우드 재측정 절차

PREP-4 이후 작성한다. 로컬에서 검증한 같은 스크립트를 클라우드 환경에서 그대로 실행하는 절차를 적는다.
